AI Agent 入门指南

第一章 什么是 AI Agent

AI Agent（智能体）是一种能够自主感知环境、做出决策并执行动作以实现特定目标的系统。与传统的聊天机器人不同，AI Agent 具备规划、记忆和工具使用的能力，能够完成更复杂的多步骤任务。

一个典型的 AI Agent 由以下几个核心组件构成：
1. 大语言模型（LLM）：作为 Agent 的大脑，负责理解和推理。
2. 规划模块（Planning）：将复杂任务拆解为可执行的子步骤。
3. 记忆模块（Memory）：存储历史对话和中间结果，支持上下文理解。
4. 工具模块（Tools）：连接外部 API、数据库或其他服务，扩展 Agent 的能力边界。

第二章 Agent 框架对比

目前主流的 Agent 开发框架有以下几种：

Google ADK 是 Google 推出的 Agent Development Kit，提供了完整的 Agent 生命周期管理。它支持多 Agent 协作、Session 状态管理、回调机制和护栏功能。ADK 还集成了 MCP 协议，可以方便地连接外部工具服务。在本项目中，financial-advisor 和 weather_agent 模块就是基于 Google ADK 构建的。

OpenAI Agents SDK 是 OpenAI 官方推出的轻量级 Agent 框架。它的设计理念是简洁和灵活，支持 Handoff 机制实现 Agent 之间的任务转移。通过 LiteLLM 集成，可以方便地切换不同的大模型提供商。本项目的 financial_research_agent 就是一个基于 OpenAI Agents SDK 的多 Agent 协作系统。

LangChain 是最早流行的 LLM 应用开发框架，提供了丰富的文档加载器、文本分割器、向量存储和 Chain 编排能力。LangGraph 是 LangChain 的扩展，专注于构建有状态的图式工作流，适合复杂的 Agent 编排场景。

第三章 文档处理与 RAG

在构建 RAG（Retrieval-Augmented Generation）系统时，文档处理是关键的第一步。典型的流程如下：

第一步，文档加载。使用文档加载器（如 TextLoader、PDFLoader、CSVLoader）将不同格式的文件加载为统一的 Document 对象。每个 Document 包含页面内容（page_content）和元数据（metadata）。

第二步，文本分割。由于大模型的上下文窗口有限，需要将长文档切分为较小的文本块。常用的分割策略包括：按字符数分割（CharacterTextSplitter）、递归字符分割（RecursiveCharacterTextSplitter）、按标记数分割（TokenTextSplitter）等。

其中 RecursiveCharacterTextSplitter 是最常用的分割器，它会依次尝试使用指定的分隔符列表进行分割。默认的分隔符列表为换行符、句号、空格等，优先在段落边界处切分，保证语义完整性。

第三步，向量化与存储。将文本块通过 Embedding 模型转换为向量，然后存入向量数据库（如 Chroma、FAISS、Pinecone）。

第四步，检索与生成。用户提问时，先从向量数据库中检索相关文本块，再将检索结果作为上下文传给大模型生成回答。

第四章 实践建议

在实际开发 Agent 应用时，有以下几点建议：

从简单开始。先构建一个单一功能的 Agent，验证核心逻辑可行后再逐步增加复杂度。不要一开始就构建多 Agent 系统。

重视测试。Agent 的行为具有一定的不确定性，需要通过单元测试和评估框架来保证输出质量。financial-advisor 项目中的 eval 目录就是一个很好的参考。

关注成本。频繁调用大模型 API 会产生较高的费用，可以通过缓存、批处理和模型选择来优化成本。

安全第一。在生产环境中，务必设置护栏机制，防止 Agent 执行危险操作或泄露敏感信息。可以参考 weather_agent 中的回调机制实现。

持续学习。Agent 技术发展迅速，建议关注最新的框架更新和社区最佳实践，保持技术敏感度。
